Common data model for innovation programmes

Organisation
NHS England
Role
Evaluation Senior Manager and Analytics Lead
Period
2026

I built a prototype platform that combines 13 datasets from 6 national innovation programmes into one data model. It recognises the same innovator or innovation across programmes, maps each one to a shared lifecycle, and presents the results in an 11-page Streamlit app.

Situation

The programmes shared no common identifiers, and few company names matched exactly between datasets. Tracing an innovator across programmes needed manual matching.

Task

Link the datasets into one model, keep an audit trail for every match, and give analysts and stakeholders a way to explore the results.

Action

  • Designed a dimensional schema of 28 tables and 7 views, with personal data redacted in the views.
  • Built an ETL pipeline in Python with Pydantic validation.
  • Matched records in tiers, logging every decision: company registration number, then exact name, then fuzzy match, then manual review.
  • Built an 11-page Streamlit app with an interactive ERD, a lifecycle funnel, a Sankey diagram, programme views, a review queue for uncertain matches, and a data quality report.
  • Added accessibility options: high contrast, larger text, keyboard focus and an NHS colour theme.
  • Wrote 42 automated tests, a synthetic data generator, separate test and production modes, and a one-command build.

Result

  • Resolved 7,000+ records into about 1,300 unique innovators and 1,400 innovations, with an audit record for every match decision.
  • The full pipeline runs in about 20 seconds.
  • The prototype formed the basis of a proposal to develop the platform further.

Skills and tools

Python, Pydantic, pandas, SQLite, dimensional modelling, entity resolution (rapidfuzz), Streamlit, Plotly, pytest, Faker, YAML configuration, accessibility design.

What I learnt

  • Linking data across programmes is mainly an audit problem. Every match needs a reason that can be traced.
  • A working prototype is the strongest argument for investment.
  • Plan security and version control from the first iteration.
