Career evidence workspace and portfolio website

Organisation
Personal project
Role
Owner
Period
2026

A version-controlled workspace that holds the evidence for my career and builds tailored CVs and this website from one master record, checking every claim automatically. I set the rules, evidence standards and review steps; an AI coding agent wrote most of the code under them, test first.

Situation

Tailoring a CV for every application let the wording drift from the evidence: figures copied forward from older CVs, and claims with no source behind them.

Task

Keep every claim traceable to a source, generate the CVs and a public website from one record, and make the rules checkable by machine.

Action

  • Made one master record the single source of truth, and generated five tailored CVs from it.
  • Designed a rule checker that runs with the tests before every commit and blocks a dropped claim or an unindexed summary.
  • Specified a static site generator in Python whose build stops if any page holds a private detail or an unsupported claim.
  • Designed a GitHub Actions pipeline with four jobs (check, build, browser tests and publish), so nothing goes live without passing every gate.
  • Worked test first, with around 350 pytest tests on synthetic data and around 50 Playwright browser tests for layout, accessibility, speed and clutter.
  • Had independent review agents check code, compliance and writing, and kept every publish behind my approval.

Result

This website, live since November 2026 and built from 25 summaries, this one included. The home page and a sample project page stay within transfer budgets set from measurement, and the accessibility tests allow no violations.

Skills and tools

Agentic AI workflows, test-driven development, pytest, Playwright and axe-core, CI/CD (GitHub Actions), static site generation in Python, git.

What I learnt

  • A rule that only a person remembers will drift, so write it as a check.
  • An AI coding agent is most useful inside tight guardrails: tests first, independent review, and a human decision before anything is published.
  • Keep plans and decisions in the repository, where every working session can find them.
