Quarterly data pipeline and assurance dashboard for Health Innovation Networks

Organisation
NHS England
Role
Evaluation Senior Manager and Analytics Lead
Period
2025 to 2026

I built a Python pipeline and a Streamlit dashboard that turn the quarterly national dataset from the 15 Health Innovation Networks into data quality reports, a data pack for each network, national strategic reports and a variation analysis.

Situation

Each quarter, a 39-table extract had to become 15 data packs and a set of national reports, all checked against the reference metrics. Doing this by hand was slow and hard to audit, and the reporting window had just been halved.

Task

Automate the quarterly cycle from extract to finished packs, with checks built in, and give stakeholders one place to explore the results.

Action

  • Built a 24-step pipeline with parallel execution. Its stages cover data profiling, data quality checks across six dimensions, building the master tables, splitting the data per network, filling each PowerPoint pack, generating strategic reports, and variation and anomaly analysis.
  • Added self-checks: a scan for unfilled placeholders, and a reconciliation of the generated metrics against the reference metrics file.
  • Built an 8-page Streamlit dashboard: national overview, network detail, project and innovation explorers, strategic impact, variation, data quality and downloads.
  • Wrote an SOP with a troubleshooting guide, documented the pipeline architecture with entity relationship diagrams, and produced data quality recommendations for the data provider.

Result

  • 15 network data packs and the national reports are produced from a single command, with automated checks.
  • The SOP lets another analyst run the quarterly cycle.

Skills and tools

Python (pandas, Plotly, matplotlib, python-pptx, python-docx, nbconvert), Streamlit, parallel processing, data quality frameworks, automated reporting, reconciliation testing, SOP and RAP documentation.

What I learnt

  • Self-checks such as placeholder scans and reconciliation catch more real errors than unit tests on simple functions.
  • Time the manual process before automating it, so the saving can be evidenced.
  • Treat the reporting period as configuration from the start, and keep the code in version control rather than copying it each quarter.
