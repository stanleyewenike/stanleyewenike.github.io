PhD: an Activity Theory-based architecture for context-aware collaboration in the cloud

Organisation
Staffordshire University
Role
PhD researcher
Period
Awarded 2023

My doctoral thesis, "An Activity Theory-Based Architecture to Enhance Context-Aware Collaboration in Software Development in the Cloud" (327 pages), proposes and demonstrates an architecture that captures and uses context to support collaboration between distributed software teams.

Situation

Moving software development to the cloud adds distribution, complexity and changing context. No theory-grounded architecture existed for context-aware collaboration.

Task

Identify the research gaps, select a theory rigorously, design an architecture grounded in it, and demonstrate it with a working proof of concept.

Action

  • Ran a systematic literature review that screened nearly 2,000 records and used thematic analysis to identify 15 research gaps.
  • Designed a formal theory-selection process that compared 5 candidate theories and selected Activity Theory.
  • Modelled context in six dimensions (who, what, when, where, why, how), adapted from the Zachman framework.
  • Designed a hybrid microservices and layered architecture with an API gateway, a service registry, an orchestrator and event-driven messaging.
  • Built a proof of concept on AWS with 29 requirements, 3 user roles and load testing.

Result

A working proof of concept, 4 contributions to knowledge, 4 published papers and 2 seminars. My four conference papers (IEEE AICCSA 2014 and 2017, FADS 2017, FTC 2017; first author on three) had 55 citations between them on Google Scholar in November 2026.

Skills and tools

Systematic review, thematic analysis, software architecture (microservices, API gateway, publish/subscribe), AWS, PHP, MySQL, Redis, requirements engineering, load testing, academic writing.

What I learnt

  • An explicit, scored selection process is a reusable method for any design decision.
  • Context modelling and service orchestration are directly relevant to today's AI agent systems.
  • Plan the evaluation at the start, with real users and quantitative measures.
