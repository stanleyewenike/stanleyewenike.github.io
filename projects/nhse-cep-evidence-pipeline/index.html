Clinical Entrepreneur Programme evidence pipeline

Organisation
NHS England
Role
Evaluation Senior Manager and Analytics Lead
Period
2026

I built a tested Python pipeline that links participants in the NHS Clinical Entrepreneur Programme to the companies they founded and to the funding and support those companies received, so that the programme's economic impact can be evidenced.

Situation

The programme lead wanted to add company, funding and support information for more than 1,700 participants. The data had no company identifiers, its company names were inconsistent, and many entries were placeholders.

Task

Add the requested fields with defensible matches, show clearly what the data can and cannot support, and make the analysis fully reproducible.

Action

  • Agreed a revised scope with the sponsor. Set separate match axes for person and company, and an evidence hierarchy in which a name-only match is never treated as confirmed.
  • Checked the cohort against public company registers, research funding databases and NHS programme data, using ranked fuzzy matching.
  • Built a data quality rules engine, a logic model and an intake schema for future cohorts.
  • Wrote 28 Python modules with a pytest suite that runs as a gate. Pinned dependencies, and recorded run manifests with input hashes.
  • Generated the reports, including an Easy Read version, with every figure in the text drawn straight from the data.
  • Identified a striking result that came from survivorship bias in one data source, and withdrew it before publication. Corrected an overstated funding total before release.

Result

  • Delivered the requested fields, and no name-only match was counted as confirmed.
  • Outputs were byte-identical across independent runs, confirmed by SHA-256 hashes.
  • Presented the evidence to senior management after peer review, and produced a specification for collecting cleaner data from future cohorts.

Skills and tools

Python (pandas, rapidfuzz, python-docx, python-pptx), Jupyter and papermill, pytest, git, record linkage and entity resolution, logic models, reproducible analytical pipelines (RAP), Easy Read reporting.

What I learnt

  • Check what a data source cannot see before claiming an effect. Withdrawing a biased finding made the remaining evidence more credible.
  • Figures generated straight from the data, plus peer review, catch errors a careful author misses.
  • Push code to a shared remote from day one, and run human review of matches alongside the automated matching.
